# Sample data

Synthetic e-commerce dataset, generated by `uv run dfdemo-generate` (seed 42) and committed so the demo
works without running anything first. Everything is fake.

| Folder | Content | Loaded with | Purpose |
|---|---|---|---|
| `batch_1/` | customers, products, orders, order_items, events (June-July 2026) | `make load-1` (truncates) | Initial full load. Last 3 days of July contain `pending` orders. |
| `batch_2/` | new customers/orders/items/events (August 2026) **plus** new snapshots of batch-1 orders (status changes) | `make load-2` (appends) | Incremental run: new rows AND updated rows (MERGE). |
| `batch_bad/` | 5 orders with a non-existent customer, 1 order line with negative quantity | `make load-bad` (appends) | Make assertions fail on purpose. |

Notes:

- `raw.orders` is an **append-only log of snapshots**: the same `order_id` can appear several times, the latest `updated_at` wins.
- Raw data is deliberately messy (mixed-case emails, lowercase country codes, capitalised devices) so the staging layer has something to clean.
- Timestamps are UTC. Every row in a batch has `updated_at` inside that batch's time window: the incremental models use it as watermark.
- Re-running `make load-1` resets everything, so the whole demo can be repeated.
