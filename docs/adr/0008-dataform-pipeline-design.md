# 0008. Dataform pipeline design and features covered
- Status: Accepted
- Date: 2026-09-18

## Context
The first 45 minutes of the stream argue why Dataform beats plain SQL; the demo must show those features
in a small but real pipeline.

## Decision
Layers: `raw` declarations -> `staging` views -> `analytics` tables. Two processes selected by tag:
- **sales** (`sales_pipeline`): `stg_customers`, `stg_products`, `stg_orders` (dedupes snapshots),
  `stg_order_items` -> `dim_customers`, `dim_products`, `fct_orders` (incremental, MERGE on `order_id`,
  partitioned by `DATE(order_ts)`, clustered) -> `mart_daily_sales` (partitioned, `post_operations`).
- **events** (`events_pipeline`): `stg_events` -> `mart_event_funnel` (columns generated by JS helpers) and
  four `daily_<step>_events` tables generated from a loop in `definitions/events/daily_event_tables.js`.
Features shown: declarations, `ref()`, DAG, config-block docs, built-in assertions (`uniqueKey`, `nonNull`,
`rowConditions`), a manual assertion, `dependOnDependencyAssertions` (bad data blocks downstream tables),
incremental with `when(incremental(), ...)`, partition/cluster config, `post_operations`, tags, `includes/`
JavaScript, programmatic action generation.
Not included in the MVP: unit tests (`type: "test"`), notebooks, data preparation, multiple environments,
`vars`.

## Consequences
+ Every Dataform advantage in the talk has a matching file in the repo.
- Assertion datasets and views appear in BigQuery (`dataform_assertions`); that is expected.

## Alternatives considered
A single larger pipeline (harder to schedule as two processes); dbt-style folders (Dataform folders are free-form).
