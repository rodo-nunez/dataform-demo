# 0006. Synthetic e-commerce dataset delivered in batches
- Status: Accepted
- Date: 2026-09-18

## Context
The demo needs data that is free, reproducible, small (cost ~0) and rich enough to show incremental loads,
messy inputs and failing assertions.

## Decision
Synthetic e-commerce data generated by `src/dataform_demo/generate_data.py` (stdlib only, seed 42) and
committed under `data/`. Tables: `customers`, `products`, `orders`, `order_items`, `events`.
Three batches (see `data/README.md`): `batch_1` (Jun-Jul 2026), `batch_2` (Aug 2026 + status changes of
batch-1 orders), `batch_bad` (orphan customer, negative quantity).
- `raw.orders` is an append-only snapshot log; `updated_at` is the incremental watermark, so every batch keeps
  its `updated_at` values inside its own time window (later batches strictly greater).
- Raw data is deliberately messy (case, whitespace) to justify a staging layer.

## Consequences
+ Deterministic, offline, no licensing, tiny (~2 MB, well inside BigQuery free tier).
+ Status changes make MERGE semantics visible, not just appends.
- Not a real dataset; numbers are meaningless.

## Alternatives considered
BigQuery public `thelook_ecommerce` (nothing to upload, and the author wants to demo loading);
Faker (extra dependency, less deterministic across versions); real open data (licensing, size).
